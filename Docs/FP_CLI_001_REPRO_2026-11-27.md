# FP-CLI-001 reproduction — 2026-11-27

Isolated Hub config: `websocket_path=/ws-alt`.

1. `GET /api/meta` returned `websocket_path: /ws-alt`.
2. A WebSocket connection to `/ws-alt` with a valid Bearer token was accepted and returned `welcome`.
3. A WebSocket connection to `/ws` was rejected with HTTP 404.
4. `ApiModels.cs` contains `ServerMetaResponse.websocket_path`.
5. `FrontlineClientBootstrap.cs` assigns `realtime.WebSocketPath = config.websocketPath;` and does not reference `meta.websocket_path`.

Conclusion: the Hub publishes a configurable WebSocket path, but the Unity client does not consume it. Non-default path deployments fail unless ServerConfig is manually synchronized.

Recommended fix (not applied): after API/Realtime schema compatibility succeeds, validate the metadata path as an origin-relative path and apply it to RealtimeClient.WebSocketPath; reject absolute URLs, query/fragment, CR/LF, backslashes and traversal segments; preserve the configured fallback when metadata is unavailable. Add /ws and /ws-alt regression cases.
